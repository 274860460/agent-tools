# 项目规划：看·拆·排·控 四步法

对任意产品/系统，按以下四步输出项目落地方案。

---

## 第①步：看全貌 — 需求诊断与范围界定

对目标系统回答以下三个问题：

| # | 诊断项 | 产出 |
|---|--------|------|
| 1 | 核心业务闭环 | 主干链路 vs 支撑功能 |
| 2 | 外部依赖 / 三方集成 | 不可控风险点清单 |
| 3 | 用户角色与规模 | 复杂度等级 → 驱动团队规模 |

---

## 第②步：拆模块 — 三层 WBS 工作分解

| 层级 | 粒度 | 示例 |
|------|------|------|
| L1 业务域 | 5~8 个 | 用户 \| 商品 \| 交易 \| 支付 \| 运营 |
| L2 功能点 | 每域 3~6 | 交易 → 下单 / 支付 / 退款 / 物流 |
| L3 任务 | 前+后+测+联调 | 下单 → 后端 2d + 前端 1.5d + 联调 0.5d + 测试 1d |

**WBS 规则**：100% 覆盖 · 8/80 规则（最底层 1~10 人天） · MECE 互斥穷尽

---

## 第③步：排计划 — 四里程碑

| 阶段 | 周期 | 核心产出 |
|------|------|----------|
| M0 预研 & 架构 | 1~2 周 | 架构文档 · 选型 · 三方 PoC |
| M1 MVP 核心链路 | 4~6 周 | 主干闭环可演示 |
| M2 功能补齐 & 联调 | 3~4 周 | 全功能 + 三方集成 |
| M3 测试 & 上线 | 2~3 周 | 压测 · 灰度 · 监控 · 回滚预案 |

**调整原则**：
- 三方集成多 → M2 拉长
- 数据迁移类 → M0 加「数据摸底」，M3 加「灰度切流」
- 替换旧系统 → 全程 +30% Buffer

---

## 第④步：控风险 — 四类风险 + MATA 策略

| 类型 | 典型场景 | 应对策略 |
|------|----------|----------|
| 技术风险 | 三方不稳定 / 选型踩坑 | M0 做 PoC；降级方案（缓存兜底、异步重试） |
| 进度风险 | 需求变更 / 估算偏差 | M1 只做 MVP；估算 +20% Buffer |
| 质量风险 | 联调阻塞 / 线上故障 | 冒烟 SOP；压测 + 回滚预案；监控先行 |
| 组织风险 | 跨部门摩擦 / 认知不对齐 | 每个里程碑 Demo Day；关键决策落 ADR |

**MATA**：**M**itigate 缓解 · **A**void 规避 · **T**ransfer 转移 · **A**ccept 接受

---

## 估算公式

```
PERT: E = (O + 4M + P) / 6
O=乐观  M=最可能  P=悲观

经验倍数: 粗估 × 1.2(Buffer) = 对外承诺工期
```
