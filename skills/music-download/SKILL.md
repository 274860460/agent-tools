## User Input

```text
$ARGUMENTS
```

> 格式：`/music-download 歌名 [歌手]`（歌手可省略）
> 示例：`/music-download 童话`、`/music-download 晴天 周杰伦`
> 若 `$ARGUMENTS` 为空或无法推断出歌名，向用户询问，**不得猜测**。

---

## 前置条件

依赖 music-search MCP server 提供的三个工具：`music_search`、`get_download_url`、`download_file`。
若工具不可用或返回 `[未配置]`（缺 `SEARCH_URL` / `SEARCH_COOKIE` 等环境变量），如实转告用户并中止，由用户完成配置后重试。

---

## 执行步骤

1. **解析输入**：从 `$ARGUMENTS` 拆出歌名与歌手（歌手可省略）。keyword 用「歌名 歌手」拼接；无歌手时只用歌名。
2. **搜索**：调用 `music_search(keyword=<拼接结果>)`，其余参数保持默认。
   - 无结果（列表为空 / total 为 0）：告知用户并建议更换关键词（如补上歌手、改用别名），中止本次流程。
3. **呈现候选**：把结果汇总为编号列表展示给用户，每项包含：歌名、歌手、专辑、时长、可用音质（`minfo` 中各 `format`/`bitrate`/`size`）。等用户选定**序号**和**音质**。
   - 用户指定歌手或要求「原唱」时，按「歌手匹配」逐条核对 `artist` 后再呈现。
   - 用户未指定音质时：默认推荐该曲目 `minfo` 中的最高可用音质（优先无损 flac，否则最高码率），并向用户说明该推荐。
4. **取下载链接**：用户确认后，取选中项的字段原样传参调用 `get_download_url`：
   - `songid` ← 结果项 `id`
   - `time` ← 结果项 `time`
   - `sign` ← 结果项 `sign`（**与该 `time` 绑定，必须原样传递，禁止编造或用当前时间戳代替**）
   - `format` / `bitrate` ← 用户所选 `minfo` 音质
5. **下载保存**：调用 `download_file(url=<上一步返回的链接>, filename="歌名-歌手")`。
   - `save_dir` 保持默认，除非用户另行指定。
6. **汇报结果**：输出保存的完整路径与文件大小。

---

## 歌手匹配

逐条核对结果项的 `artist`，两类误判都要防：

- **不以记忆认定原唱**：先按歌名搜索，用结果反查原唱是谁；记错歌手会带偏关键词（实测教训：《若把你》误记为郑鱼，实为 Kirsty刘瑾睿）。
- **形似名不是本人**：「卓玛云朵」「云朵朵」≠「云朵」；`name` 带 DJ版/烟嗓版/cover/xx版 后缀的一律是改编翻唱，直接排除。
- **录入名不规整 ≠ 不是本人**：平台条目的艺人名可能错乱——实测 kuwo 搜《若把你》首条 `artist` 显示「Kirstyy瑾」，即 Kirsty刘瑾睿 的条目（与网页端首条一致）。歌名/专辑吻合但 `artist` 存疑时，把该条目列给用户确认，不要直接判定"没有原唱"。
- **交叉验证**：组合搜不到时换关键词（歌名+歌手 / 纯歌手名翻目录）、翻页、换平台；各平台都没有再如实告知。

---

## 边界与纪律

- `id`/`time`/`sign` 只能来自本次 `music_search` 的返回项，禁止凭记忆或推测填写。
- 任一步工具返回以 `[失败]` 开头的信息时，按「故障排查」分类定位、如实转告用户；禁止编造参数或凭猜测重试。

---

## 故障排查

按返回形式分类：

| 症状 | 原因 | 处理 |
|------|------|------|
| `HTTP 468`（响应是 HTML 挑战页） | 站点前置 SafeLine WAF 的 JS 挑战：`SEARCH_COOKIE` 中 `sl-session`/`sl_jwt_session` 失效或被限频 | 先停手等几分钟再试（临时限频可自愈）；持续 468 → 请用户在浏览器打开搜索站点（挑战自动完成），F12 复制最新 cookie 更新 MCP 配置的 `SEARCH_COOKIE`。本会话内可不重启：三个工具都有 `cookie` 参数，逐次传入新 cookie 即可（参数优先于环境变量） |
| `code=-1 … 接口异常`（取链接时） | 后端真实业务失败（HTTP 200 的 JSON 答复），非 WAF/网络问题；实测存在某平台搜索正常但取链通道整体故障的情况 | 换平台重新搜索，用新平台结果项的 `id`/`time`/`sign` 取链；各平台均失败则属服务端故障，如实告知 |

已验证事实：

- `platform` 支持 `kuwo`（默认）、`wyy`（网易云）；kuwo 的 `duration` 单位是秒，wyy 是毫秒。
- 后端忽略 `size`，固定每页 20 条，翻页只用 `page`。
- 不要用 curl 直接请求接口排查：缺浏览器指纹会被 WAF 挑战，密集请求会加重限频。
