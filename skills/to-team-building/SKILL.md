# 团队搭建：定·配·建·转 四步法

对任意产品/系统，按以下四步输出团队搭建方案。

---

## 第①步：定架构 — 康威定律驱动的组织设计

**原则**：按业务域切团队，而非按职能切。团队结构映射系统架构。

- **逆康威法则**：先设计目标架构 → 再反向设计团队结构
- 输入来源：项目规划第②步的 L1 业务域拆分

**Team Topologies 四种团队类型**：

| 类型 | 定位 | 举例 |
|------|------|------|
| Stream-aligned（流对齐） | 端到端交付业务价值的主力 | 交易组、用户组 |
| Platform（平台） | 内部 X-as-a-Service | 基础架构组、CI/CD 平台 |
| Enabling（赋能） | 临时嵌入、帮主力提能力 | AI 工具链推广组 |
| Complicated-Subsystem（复杂子系统） | 高认知负荷组件 | 支付引擎、清算引擎 |

---

## 第②步：配梯队 — 角色与人员配比

**标准配比（10 人以下团队）**：

| 角色 | 人数 | 职责 |
|------|------|------|
| 技术负责人 | 1 | 架构选型 · 方案评审 · 跨组协调 · 关键 CR |
| 后端 | 3~4 | 核心业务 · 接口 · DB |
| 前端 | 1~2 | UI · 前后端联调 |
| 测试 | 1 | 用例 · 冒烟 · 回归 |
| UI/UX | 0.5~1 | 可共享或外包 |

**推导公式**：
- 每 3~5 模块 ≈ 1 后端 + 0.5 前端
- 后端 : 前端 = 2:1 ~ 3:1
- 开发 : 测试 = 4:1 ~ 6:1

**梯队金字塔**：
- P7/P8 架构师 1 人 = 定海神针
- P6 骨干 40~50% = 独当一面
- P5 及以下 40~50% = 执行层 + 蓄水池

---

## 第③步：建机制 — 五大协作纪律

| 机制 | 频率 | 要点 |
|------|------|------|
| 技术方案评审 | 新功能启动前 | 统一模板 · SDD（先写规格再写代码） |
| Code Review | 每个 PR | 200~400 行/PR · 自动化前置 · 4~8h 响应 SLA |
| 站会 | 每日 ≤15min | 完成/计划/阻塞 · 深度走 Parking Lot |
| 里程碑 Demo | 每个 M 节点 | 跟业务方对齐预期 |
| 复盘 Retro | 每迭代结束 | ADR 沉淀 · Blameless |

**工程规范三件套**：
1. 接口契约先行
2. CI/CD 流水线（自动化构建 + 测试门禁 + 零停机发布）
3. 监控告警先行（Prometheus + Grafana + ELK）

---

## 第④步：转飞轮 — 知识沉淀 & 梯队培养

- **知识沉淀**：ADR + CodeGraph + Memory → 新人快速上手
- **梯队培养**：核心模块 AB 角 → 消除单点风险（Bus Factor ≥ 2）
- **AI 提效**：AI 工具集成日常流程，释放高级工程师精力到架构层
